# Course Reflection

The most difficult concept for me during this course was grasping asynchronous JavaScript—specifically, transitioning my mindset from synchronous, top-to-bottom execution to managing the non-blocking nature of Promises and `async/await`. Initially, it was challenging to track the control flow, particularly when network requests failed or race conditions occurred in the DOM. I overcame this by heavily utilizing the `console.log()` debugger and the browser's Network tab. Breaking down `fetch()` requests into step-by-step processes and mapping out the exact journey of a payload from the client to the server and back made the abstract concepts concrete.

Based on the feedback I received during the capstone preparation phase, the key area I want to improve is frontend network safety. While I successfully handled UI states (loading, success, error) and implemented defensive DOM manipulation using `textContent`, I realized my client-side logic is vulnerable if a user triggers rapid, repeated requests or navigates away before a fetch completes. I intend to improve this by integrating an `AbortController` into my request utilities to cancel pending API calls safely, preventing memory leaks and UI race conditions.

Moving forward, my next learning objective is to dive deep into backend engineering. I want to learn how to build the APIs I've been designing by mastering a framework like Node.js with Express. I am particularly excited to implement the exact tools needed to handle transactional safety and queue management like the ones designed in this capstone, utilizing robust databases like PostgreSQL to transition confidently into a true Full-Stack Engineering role.
